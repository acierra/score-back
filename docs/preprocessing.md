# Предобработка стереопары — задача 12

## Подключение

Общий модуль используется в `CloudPointClient` (Unity, пункты CLI 4–6)
и в `scared_dataset_benchmark`:

```text
decode → gray → StereoRectifier → StereoPreprocessorChain
       → StereoMatcher → PointCloudBuilder → export / evaluation
```

Предобработка принимает уже ректифицированные `CV_8UC1` изображения,
сохраняет размер и координатную сетку, не изменяет исходные буферы.
Цветное изображение для viewer сохраняется без фотометрической обработки.
Калибровка, Q, параметры matcher и фильтрация облака не меняются.

`IStereoPreprocessor` — интерфейс отдельного обработчика стереопары.
`StereoPreprocessorChain` последовательно вызывает все настроенные шаги.
Это вариант цепочки обработчиков: порядок задаётся списком, каждый шаг
передаёт результат следующему. Остановка на первом обработчике здесь
не нужна, поскольку требуется композиция нескольких алгоритмов.
Новые обработчики можно подключать через `append(unique_ptr<...>)`;
для выбора из YAML также потребуется добавить метод в создание шагов,
парсер и проверку настроек.

## Настройка YAML

Отсутствие секции, `chain: []`, единственный шаг `method: none`
или `enabled: false` означают baseline без обработки. Существующие
конфигурации и вызовы C++ продолжают работать после пересборки.
Неизвестные имена, лишние ключи и недопустимые значения вызывают ошибку,
в том числе при `enabled: false`.

Пример цепочки подавления шума и CLAHE:

```yaml
cloud_point:
  preprocessing:
    enabled: true
    chain:
      - method: edge_preserving_denoise
        diameter: 5
        sigma_color: 20.0
        sigma_space: 5.0
      - method: clahe
        statistics: independent
        clip_limit: 2.0
        tile_grid_size: 8
```

Готовые отдельные варианты: `configs/preprocessing/*.yml`.

| Метод | Поведение и параметры |
|---|---|
| `none` | Передаёт вход без копирования пикселей |
| `pair_normalize` | Среднее и стандартное отклонение правого изображения приводятся к левому; обязательно `statistics: left_reference`, `epsilon` защищает от деления на почти нулевое отклонение |
| `clahe` | CLAHE на сером изображении; обязательно `statistics: independent`; `clip_limit`, `tile_grid_size` задают ограничение и число плиток по каждой оси |
| `local_normalize` | Локальные среднее и отклонение, общий целевой уровень и контраст из объединённой статистики пары; `statistics: independent` относится к локальным статистикам; `window_size`, `epsilon` |
| `illumination_correction` | Деление яркости на локальное среднее с общим целевым средним пары; `statistics: independent`, `window_size`, `epsilon`. Простая коррекция, не реализация Retinex |
| `edge_preserving_denoise` | Bilateral-фильтр с одинаковыми фиксированными `diameter`, `sigma_color`, `sigma_space` для обеих камер |
| `specular_mask` | Помечает пиксели яркостью >= `brightness_threshold` (245) как ненадёжные и расширяет область на `dilation_radius` (1). Пиксели изображения не закрашиваются |

Все выходы ограничены диапазоном 0–255. `local_normalize` — базовый
вариант локальной нормализации типа Wallis, а не полный параметрический
фильтр Wallis. Независимая адаптация камер разрешена только явно: её
влияние на соответствия необходимо измерять, улучшение не гарантируется.
Объекты цепочки не потокобезопасны; используется отдельный объект на pipeline.
Результат `none` может ссылаться на вход — его нельзя изменять на месте.

`specular_mask` возвращает две маски надёжности (0 — исключить, 255 — оставить).
Они накапливаются в цепочке и применяются к disparity перед репроекцией:
проверяется левый пиксель и правый пиксель по координате `x_right=x_left-d`,
а для дробного disparity — оба соседних отсчёта. Поэтому правый блик
исключает соответствующую левую точку, а не точку с тем же номером столбца.
Рекомендуемый порядок — маска перед усилением контраста. В текущем сером
pipeline это пороговый детектор ярких кандидатов в блики; насыщенность
цвета не анализируется, яркая ткань тоже может быть исключена.

## Проверка и сравнение

```bash
meson setup build
meson compile -C build
meson test -C build --print-errorlogs

# В benchmark этот файл задаёт только предобработку.
# Остальные YAML-настройки, включая глубину, не применяются.
./build/src/cloud_point/scared_dataset_benchmark \
  --preprocessing-config=configs/preprocessing/clahe.yml \
  --preprocessing-export=out/clahe-keyframe0 \
  /path/to/keyframe_0 160 - 0.02 0.30
```

JSON дополнен `settings.preprocessing` и `preprocessing_ms`.
Время применения масок после matcher включается в `preprocessing_ms`.
`preprocessing_masked_points` показывает число дополнительно исключённых
соответствий, а `coverage_loss.preprocessing_mask` выделяет эту потерю
покрытия отдельно от отказов matcher (с сохранением приоритета причин
«вне диапазона поиска» и «граница изображения»).
`matching_ms` измеряет только matcher. Экспорт по запросу сохраняет
ректифицированную и обработанную пары PNG и `matcher_disparity.yml.gz`.
Карта `CV_16S` хранится в масштабе ×16 и уже включает включённые
постфильтры matcher (WLS/median). Для необработанной карты отключите их.
Запись файлов не входит во время предобработки и сопоставления.
При наличии масок также сохраняются `left_valid_mask.png`,
`right_valid_mask.png` и `masked_disparity.yml.gz`; `matcher_disparity.yml.gz`
содержит выход matcher до применения масок.

Для DoD сравниваются одинаковые кадры с `point_cloud.obj`:

```bash
python3 scripts/compare_preprocessing.py \
  --bench build/src/cloud_point/scared_dataset_benchmark \
  --variant clahe=configs/preprocessing/clahe.yml \
  --variant normalize=configs/preprocessing/pair_normalize.yml \
  --output out/preprocessing-comparison \
  /path/to/keyframe_0 /path/to/keyframe_1
```

Baseline `none` запускается автоматически. Дополнительные методы
подключаются повторением `--variant NAME=YAML`. Скрипт сохраняет JSON
и CSV: исходные метрики, разницу с baseline по каждому кадру, команды,
настройки и контрольные суммы конфигураций и исполняемого файла.
Скрипт использует фиксированный CPU StereoSGBM, 160 уровней диспаритета
и диапазон глубины 0.02–0.30 м. Это можно изменить общими параметрами
`--disparities`, `--min-depth-m`, `--max-depth-m`; значения одинаковы
для baseline и всех вариантов.
Общие флаги matcher передаются как `--bench-arg=--block-size=5`.
Ошибка запуска, отсутствие эталона или отсутствие оцениваемых точек
дают статус ошибки, а не нулевую геометрическую ошибку.

Без настоящих кадров с эталоном этот скрипт проверяет инфраструктуру,
но не доказывает улучшение точности. Для окончательного DoD нужны
экспериментальные результаты на SCARED. Для задачи 12 выполнены 48 запусков
на шести настоящих кадрах; результаты и происхождение данных описаны в
[подробном отчёте](task12-report.md), исходные метрики — в `reports/task12/`.
SERV-CT,
метрики disparity и региональные маски остаются отдельными расширениями
плана обзора; в текущую реализацию они не включены.
