# Proposal

## Why

Checking a reconstruction today means reading JSON numbers or loading a PLY into a third-party web viewer. Meshy, for example, draws vertex-only clouds as fans of slivers and hangs on large files. A one-off three.js viewer built during exploration (every SCARED keyframe, coloured by 3D error against ground truth) turned out to be the quickest way to judge quality. It lives outside the repo, though, and cannot be regenerated. The benchmark results also only come out as a Markdown table printed to stdout, so they cannot go into spreadsheets or be compared between runs.

## What Changes

- Add a self-contained, offline web point-cloud viewer to the repo. It is a static HTML/JS page with vendored three.js. It shows one or more clouds with orbit, pan and zoom, and colours points by camera image, depth, 3D error or signed depth bias. It can overlay ground truth and shows per-frame metrics, an error histogram and a depth-bias chart when ground truth exists.
- Add a compact viewer data export: a stride-decimated grid of reconstructed XYZ, optional rectified ground-truth XYZ and RGB. `scared_dataset_benchmark` writes it on request; the CLI writes it for a cloud computed over RPC.
- **Dataset launch:** `scripts/scared_overview.py --view` runs the benchmark over the given keyframes and builds a viewer site with every frame and its metrics. It then opens the site in the browser straight from disk; no server is needed. `--view-out DIR` sets where the site goes, `--no-open` skips the browser, and `--serve [PORT]` serves the site on 127.0.0.1 for headless or Docker use.
- **CLI launch:** add a new `cloud_point_rpc_cli` menu option, "compute-cloud + open viewer". It computes the cloud over RPC (e.g. from Unity or `scared_dataset_server`), adds the frame to a viewer site and opens it in the browser. There is no ground truth, so only the image and depth colourings are available.
- **Tables:** `scripts/scared_overview.py --csv PATH` and `--xlsx PATH` write the per-keyframe metrics. CSV uses only the standard library. XLSX needs `openpyxl`; if it is missing, the script exits with a clear message before running the benchmark. The existing Markdown output stays the default.
- Add `openpyxl` (python3-openpyxl) to the Docker dev image.

Out of scope: work on reconstruction accuracy, such as the depth-dependent z bias, outlier filtering and coverage. That will be a separate change once this tooling exists.

## Capabilities

### New Capabilities
- `cloud-viewer`: the offline web viewer page, its data export format, and launching it from the dataset tooling and from the CLI.
- `quality-reports`: tabular (CSV/XLSX) export of per-keyframe reconstruction metrics from the SCARED overview tool.

## Impact

- **C++:** `src/cloud_point/scared_dataset_benchmark.cpp` gets an optional viewer-export argument. A new viewer-export function goes next to `write_ply` in `cloud_point_client` (header `include/cloud_point/cloud_point_client.hpp`). `src/cli.cpp` gets a new menu option, and `CliStereoOptions` gains viewer settings, which also go into `config.hpp` and `config.yaml.example`.
- **Python:** `scripts/scared_overview.py` gets new flags. A new `scripts/cloud_viewer/` holds the static page, vendored three.js r128 with OrbitControls (MIT) and a small site builder/server helper.
- **Tests:** a GTest for the export format; extended `tests/test_cli.cpp` for the menu entry; tests for the Python table writers.
- **Dependencies:** optional `openpyxl`. The Dockerfile installs it. No new C++ dependencies.
- **Docs:** README (usage), `openwiki/build-and-testing.md` and quickstart links (regenerated by OpenWiki rather than hand-edited), and `config.yaml.example`.
